A single-address-space unikernel that boots through GRUB into 64-bit long mode and runs a neural network in ring 0. No scheduler, no syscalls, no libc, no filesystem — the weights arrive as a GRUB module and the first forward pass starts within milliseconds.

What is not in this image

  • Multi-process scheduler
  • Ring 3 / ring 0 transitions
  • POSIX subsystem and syscalls
  • Virtual file system and disk driver
  • Networking stack and daemons
  • User accounts and permission checks

A general-purpose kernel exists to arbitrate between competing programs. This workload has exactly one program, so the arbitration layer is removed rather than configured away.

03

Adaptive execution engine

The kernel ships three mathematically equivalent forward passes (portable scalar, AVX2, AVX2+FMA). At boot it probes CPUID, enables the AVX state machine itself, times every eligible kernel, gates every SIMD path against the scalar reference, and selects by measurement — never by a capability guess.

06

Method and honest caveats

The numbers are reproducible from the commands below, and the limits of the comparison are stated rather than hidden.

How it was measured

  1. 01Train on MNIST or generate demo fixtures, then freeze the model and samples.
  2. 02Package the kernel and both modules into a GRUB Multiboot2 ISO.
  3. 03Boot the ISO in QEMU with the serial port captured to a file.
  4. 04Calibrate the timestamp counter against PIT channel 2, then time every pass.
  5. 05Probe CPUID, enable the AVX state, measure every eligible kernel, gate on correctness.
  6. 06Run the same engine natively and diff the results.
  7. 07Generate this report from the raw transcripts.
make bench builds, boots, measures and regenerates this page

Limits of this comparison

  • Not a scheduler benchmark. The QEMU guest is not a second Linux install in the same VM configuration, so the cross-run latency ratio describes these two environments, not a universal speedup.
  • Emulated CPU. Timing per instruction inside QEMU differs from bare silicon, and the boot figure is dominated by first-execution code translation. The methodology, not the absolute number, is the transferable result. This is also why the dispatch policy measures instead of trusting CPUID: AVX2 runs 3.2× slower than scalar under TCG while being faster on silicon.
  • Timer overhead. Each pass includes one fenced timestamp read, which is a fixed few tens of cycles.
  • Numerical tolerance. SIMD kernels reorder float32 sums; predictions are identical and logits agree to within the 500e-6 gate, but bit-exact equality is neither expected nor required.
